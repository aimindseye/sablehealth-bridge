# R11.3 — sleep compatibility candidate

Owner approved comprehensive compatibility after two real-device parser holds. Parent: 70311ed98b7bea94a53a2d2107c834e1eebae3be. PR #8 remains draft. This is not an Android CI or device-qualified release.

References (stable v4): https://developers.google.com/health/reference/rest/v4/users.dataTypes.dataPoints ; https://developers.google.com/health/data-types/sleep ; https://developer.android.com/reference/kotlin/androidx/health/connect/client/records/SleepSessionRecord .

- Optional type/metadata/stages; CLASSIC, detailed, unspecified, future types, naps, gaps and session-only records. Explicit unfinished processing is deferred. RESTLESS/unknown primary stages map to UNKNOWN rather than falsely counted asleep; ASLEEP maps to generic sleeping.
- Google defines its asleep total from primary stages; micro-awakenings are separate. Preserve these in memory and show union duration, infer meaning from the collection, disclose noncanonical types. Out-of-bed takes precedence in the Health Connect timeline. Missing stage time stays unclassified. Google summary fields and per-stage summaries, revisions and classification remain in memory; no persistence or new permissions.
- Manual recent history: 14 local calendar days, individual eligible sessions, newest main sessions first, previous/next review. Identical records deduplicate; conflicting keys/overlapping source bounds held, including a malformed or unfinished record with known overlapping bounds. Unrelated malformed records do not block valid ones. Incomplete pagination stops the whole read. Background probe uses same parser in original three-day window and remains read-only.
- Source identity required; existing key derivation unchanged. Fresh selected session must match preview, and Health Connect decision is rechecked. No foreign record overwrite, no removal of unmatched records, no replacement of detailed owned data with an empty stage list. A changed same-ID interval requires an explicit manually-edited source flag and update timestamp; source revision is not stored durably; automated revision reconciliation is not qualified.
- Bounded read retry with jitter for temporary status or I/O; no write retry, no automatic token renewal. 401 asks for reconnection. No endpoint, dependency, manifest, permission or CI policy change. Recording method and baseline device form factors map from source attribution; unknown or unsupported values use unknown rather than guessing. Explicit Health Connect sources are excluded to prevent round-trip copying.
- Diagnostics exposes selectable fixed-schema field presence and allowlisted enum categories (OTHER/MISSING for unfamiliar values), no arbitrary keys, values, dates, health IDs, durations, counts, or tokens. Generated only from successful complete retrieval; no raw response export, automatic clipboard write, telemetry or files.
- Actual Google account data unavailable to author. Real-payload shape review and source/Health Connect/Sable Health accuracy comparison mandatory; no public distribution or automatic writes. Source policy for redistribution unresolved. Longer historical backfill, durable source revisions, full automatic auth/scheduling, full stage-summary UI and cross-app distribution not claimed complete.

Quality: unchanged checks plus cumulative and incremental >=80% new-code coverage, actual documented API regression cases, Android CI, fresh dependency and manifest verification. No owner test requested until author-side CI review passes.
