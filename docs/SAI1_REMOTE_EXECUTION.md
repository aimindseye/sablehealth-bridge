# SAI-1 remote execution integration

The independently distributed SAI-1 host/client package is installed by the owner outside both source repositories. The host worker runs as the isolated build identity; the checked-in entrypoint only dispatches to the installed client. Configure `SAI1_HOST` locally (private SSH destination, not committed). From a clean, reviewed, published candidate checkout, run `bash tools/test-remote.sh --full`. The client selects the exact commit; the host executes the existing repository full preflight and a headless Q25 application launch smoke test, then returns a manifest-checked evidence archive. Interactive SSH sudo authorization may be required once per run. No unrestricted passwordless sudo, release signing or publishing is enabled.

The `--full` option refers to the existing executable preflight plus headless smoke, not yet the future instrumentation/golden screenshot suite. New UI instrumentation, golden comparisons, protected release signing and physical-device acceptance remain distinct gates. Current release scripts, existing CI and quality thresholds remain unchanged. Do not treat remote smoke evidence as release qualification. Do not commit host credentials, signing material, private evidence or health records. Use the independently verified package receipt to track the installed client/worker version.
