# SAI-1 v2 remote execution integration

Use one canonical Mac checkout per repository: `~/Documents/projects/sablehealth` and `~/Documents/projects/sablehealth-bridge`. Retain archived worktrees and evidence until recovery is independently verified. Ubuntu `ai-g732` runs isolated exact-commit build workspaces; the Mac controls runs and physical-device acceptance. Install the independently distributed, owner-reviewed v2 host/client package outside both repositories. Set `SAI1_HOST` locally; from a clean, reviewed and published checkout run `bash tools/test-remote.sh --full`. The client resolves current published main as the coverage base; a stale or divergent candidate is held, not silently rebased.

The v2 worker uses a transient systemd service with CPU quota 400%, memory max 12 GiB, swap max zero and 512 tasks, verifies cgroup limits, checks prerequisites including Gitleaks 8.30.1, executes existing repository full preflight, enforces at least 80% changed executable line-plus-condition coverage independently per app/core module using JaCoCo, and captures a Q25 launch smoke screenshot. The owner receives a manifest-checked evidence archive. Interactive SSH sudo authorization may be required. No unrestricted passwordless sudo or publishing. GitHub CI, SonarCloud, CodeQL, MobSF and existing stricter coverage gates remain independently mandatory; unchanged main has no differential executable changes, not a new-code coverage percentage.

Release signing is a separate owner-only action using independently verified root-protected SDK tools, LUKS-backed key storage, exact input hash, protected staging and registered certificate verification. It is not authorized until host rehearsal, tool provenance and encrypted migration are verified. Existing release scripts are unchanged and remain the fallback. Never provide key/password material to build identities, CI or ChatGPT. Exact-head CI and release approval remain owner decisions. The `--full` scope is existing preflight, differential coverage and launch smoke, not native instrumentation, approved visual regression or physical-device acceptance. Keep private evidence outside source trees; do not commit health records, credentials or host details. Retain run archives under owner control; no automatic deletion of evidence or recovery artifacts.
