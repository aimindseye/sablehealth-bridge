# R11.4 automatic sleep sync — implementation and qualification history

**Status update (2026-11-26):** the implementation is accepted for owner merge; unattended operation and safety acceptance remain open. See [the current acceptance record](R114_IMPLEMENTATION_ACCEPTANCE_2026-11-26.md) and [issue #10](https://github.com/aimindseye/sablehealth-bridge/issues/10). The following sections preserve historical candidate-stage instructions and CI corrections; they are not the current release decision.

## Scope and deliberate safety restriction

R11.3 anchor: a6292dcc46694444af476298c61d5b78b4dcee1a; PR 8 remains unchanged and unmerged. R11.4 is a stacked candidate against that exact source. Default OFF. Foreground explicit consent requests only the existing sleep read/write plus background read permission and sleep-only Google scope. Enable binds the selected Google account using a salted local hash. A different account pauses sync; re-enable requires the original account. No refresh token, access token, account name, raw sleep payload or raw record identifier is persisted. No new dependency, permission, service or receiver. Existing backup exclusions and read-only probe are preserved.

Unique network-constrained WorkManager periodic work defaults to 30 minutes; selectable 15/30/60 before enabling. A unique immediate request is scheduled on enable, foreground return, and Sync now. WorkManager may defer work, and force-stop prevents unattended execution until app reopening. The first complete run scans 14 calendar days, subsequent runs scan 7. Read retries remain bounded. The worker never launches an interactive authorization intent. Reauthorization or permission loss pauses sync. Consent generation is rechecked and invalidates stale requests after stop or re-enable. No work may start a new write after observing revoked consent; a write already submitted can complete.

The initial unattended implementation is **insert-only**. Completed source sessions with usable stages and known successful stage processing may be inserted only after a fresh Health Connect decision inside the shared manual/automatic write mutex. Exact existing records are verified and skipped. Conflict, source uncertainty, updates, deletion and prior confirmed-but-missing sessions are held. A durable journal reserves an opaque identity before any insert, records confirmation only after readback, and holds unresolved attempts rather than blindly repeating them. The journal is retained across disable/re-enable and never pruned to permit new writes. It cannot protect records deleted before first observation or after application data is cleared. An unattended revision ledger with authoritative ordering and exact prior record verification is not implemented: modifications remain explicitly manual, including Bridge-owned revisions. Foreign records are never modified or deleted by automation. No additional remote backend. Status, counts and the five most recent run summaries are local aggregate metadata.

## Qualification

The draft branch is an implementation candidate, not a ZIP/APK handoff. Real Android compile, full ktlint/Detekt, debug/release Lint, all tests, SonarCloud, Gitleaks, CodeQL and exact MobSF checks must be green. Actual JaCoCo incremental and cumulative line+branch coverage >=80% per module, and fresh dependency inventories/OSV and license/manifest comparisons are required. No gate changes or new exceptions permitted. The CI diagnostic step may run the actual formatter and publish a source patch after a failed job, but cannot make that job successful or modify a branch. Do not merge or install an unqualified candidate.

## Physical acceptance — after qualification and signed APK verification

Use Q25 on the existing same Google account. Confirm existing manual preview and prior records intact. Keep auto OFF, verify no writes. Run 2-minute and 75-minute read-only probes while app closed; record actual PASS_READ_ONLY or failure. Enable explicitly, grant sleep/background access, confirm first 14-day sync and readback. Compare current-day Sable Health Dashboard and Sleep tab after foreground refresh. Verify repeat runs and multiple requests create no duplicate; compare writer/date and count in Health Connect. Select 15 minutes for controlled test (stop/re-enable, default remains 30). Return Home, do not force-stop or reopen; observe a later new Fitbit sleep after Google export and confirm worker imports it without opening Bridge. Test after >75 minutes, screen off, reboot, offline then reconnect, permission loss, authorization resolution, account mismatch, disable, uncertain-write and conflict behavior as safely observable; use synthetic fixtures for destructive/uncertain scenarios, never delete personal data merely to test. Check that neither manual nor automatic sync resurrects a journaled deletion automatically; manual actions remain user-authorized. Record unobserved cases honestly, never mark simulated results as physical proof. Titan 2 compact UI smoke test. Public distribution remains held for Google/Health Connect attribution, license notices and accepted pre-release dependency risks.
