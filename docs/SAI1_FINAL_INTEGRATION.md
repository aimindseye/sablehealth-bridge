# SAI-1 final integration and housekeeping

Use one canonical Mac checkout per repository. The existing v2 remote test client, cgroup limits, full repository preflight, independent differential coverage gate and headless launch smoke remain unchanged. Install the independently distributed final coordinator on Mac and Ubuntu. `bash tools/build-release.sh --remote` builds the exact published main commit on Ubuntu; `--remote --run <run-id>` uses already qualified evidence for that exact commit. The owner explicitly attests exact-head CI, SonarCloud, CodeQL, MobSF, candidate differential coverage and device/release acceptance; the coordinator does not fetch or certify those independent approvals. Draft candidates are refused for signing. Existing local release commands retain their original arguments and behavior. The registered key stays inside the LUKS vault; the root-protected coordinator opens it interactively, uses the independently qualified signer, closes it before transfer, and exports only the verified signed APK and receipt. Mac independently checks signature, certificate, alignment, metadata and hash. No automatic publishing. A recovery-only `--remote --run <run-id> --retrieve` retrieves an already signed archive without signing again. Retain the original evidence and workspace until release acceptance; Health requires the R8 mapping file to remain present. Actual production signing and retrieval remain pending the first authorized release.

## Housekeeping is part of every deliverable

After installation and owner acceptance, preview cleanup on Mac and Ubuntu using the installed `housekeeping.py`. Apply only after verifying the previous package ZIPs on Mac and confirming the new installation. Keep one verified ZIP per version in `~/Documents/sai1-deliverables`; remove checksum-matched extracted delivery copies and superseded owner staging directories only. Unknown or modified files, symlinks and mounts are held for review. Do not use broad glob deletion or `git clean`. Preserve signing keys, vaults, encrypted recovery copies, signed releases, acceptance evidence, historical Git worktrees and qualified rollback tools. Temporary build workspaces, remote evidence exports and other unknown paths require explicit run-specific retention decisions; no automatic deletion of these in this release. Future deliveries must provide a checksum allowlist and cleanup instructions covering both machines, including a post-acceptance cleanup receipt. Do not upload private evidence, credentials, or recovery material to GitHub.
